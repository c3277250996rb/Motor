# 正点原子 F407 BLDC 无感控制完整实现（基于 zero_ctr.c 源码）

> 方案：**反电动势过零检测法（三段式启动：预定位→开环升频升压强拖→检测稳定过零点→切换闭环 30° 延迟换相）**

## 一、核心原理

BLDC 无感不能直接读取转子位置；电机转动时**未导通的那一相绕组会产生反电动势 BEMF**。

1. 反电动势**过零点超前理想换相点 30° 电角度**；检测到过零后，**延迟 30° 电角度再执行换相**，电机才能持续输出转矩。
2. 电机静止转速 = 0，**没有反电动势，无法检测过零点**，必须用开环 V/F（升频升压）强拖把电机转起来，反电动势足够大之后，再切闭环过零控制。

## 二、整体软件流程（状态机`zero_ctr_loop()`）

`g_zero_ctr_status`状态：

- 0：转子预定位
- 1：定时延迟，同时后台检测过零信号
- 2：开环加速换相（升频升压）
- 3：闭环过零运行

### 阶段 1：预定位 case0（status=0）

```c
g_vvvf_sp.Voilage_Ref = (uint16_t)(MAX_PWM_DUTY/20);
g_bldc_motor1.pwm_duty = g_vvvf_sp.Voilage_Ref;
m1_uhvl();  //U+ V- 固定两相导通，把转子强制拉到已知机械位置
g_vvvf_sp.Freq_T_Ref = 1100; //初始换相间隔时间
g_zero_ctr_status = 1;
```

作用：消除转子初始角度不确定性，保证启动不会反转、抖动；**不能给太高 PWM，防止过流**CSDN博...。

### 阶段 2：开环强拖加速（status=1 + status=2，VVVF 升频升压）

1. **case1 定时延迟**：`g_delay_temp`计数，计数到`Freq_T_Ref`，进入 case2；
   同时调用`hallless_sw()`持续读取三路过零 GPIO，做软件滤波，尝试捕获稳定过零信号；
   如果连续检测到稳定过零信号，直接跳转到 status=3，退出开环。
2. **case2 开环换相 + 升频升压**

```c
g_vvvf_sp.Freq_T_Ref -= g_vvvf_sp.Freq_T_Ref/15+1; //缩短换相周期 = 提高旋转频率
change_voltage(); //随换相次数，逐步提高PWM占空比（升压）
anwerfen_sw();   //六步换相，按正/反转向依次输出驱动：U+V- →U+W- →V+W- …
```

- `Freq_T_Ref`：换相间隔时间，不断减小，最小钳位到 180；间隔越小转速越高。
- `change_voltage()`：根据开环换相计数 Count，逐步加大 PWM 占空比，频率升高同时电压升高，匹配电机反电动势，防止失步。
- `anwerfen_sw()`：六步换相查表，区分 CCW 逆时针、CW 顺时针两套导通序列。

> 开环阶段电机完全不看反电动势，纯粹软件计时强制换相，把电机 “拖” 到一定转速，让反电动势幅值足够被比较器识别。

### 阶段 3：检测到稳定过零点，切入闭环 status=3

当`hallless_sw()`返回 1（`switch_hallless ==1`），状态切 3，进入闭环运行，**不再使用开环计时换相，全部由反电动势过零信号决定换相时刻**。

## 三、闭环核心函数 `hallless_sw()` —— 过零检测、滤波、测速、30° 延迟换相

### 1）过零信号软件消抖滤波

```c
//移位寄存器滤波 Queue_Status[0/1/2]对应U/V/W三相
g_hallless_three.Queue_Status[0] = g_hallless_three.Queue_Status[0] << 1;
g_hallless_three.Queue_Status[0] |= HAL_GPIO_ReadPin(比较器输出GPIO);
```

`FILTER_LONG=0xFF`：移位寄存器 8bit；**连续 8 次采样全部为 1 才判定电平为 1；全部 0 才判定为 0**，中间混杂返回 0（信号不稳定），过滤 PWM 带来的毛刺噪声。

### 2）边沿检测 uemf_edge ()

检测滤波后的 U 相过零信号的跳变沿（0→1 /1→0），捕捉真实过零事件，返回边沿状态。

### 3）电机转速计算

`count_j`是中断计数（18kHz 中断频率）；每次捕获有效过零边沿，清零 count_j；

> 转速公式：`Speed_RPM = SPEED_COEFF / count_j`；再调用一阶 RC 低通`FirstOrderRC_LPF`做转速平滑滤波。

### 4）30° 电角度延时计算与换相（最关键）

理论：过零点距离理想换相点为**30° 电角度，一个完整 60° 换相时间是 count_j**，因此 30° 时间 = `count_j / 6`，存入`Filter_Delay`。

```c
g_hallless_three.Filter_Delay = count_j / 6;  //动态计算30°对应的计数时间
```

逻辑：

1. 检测到三相过零状态`Hallless_State`发生改变（过零事件到来），启动计数`Filter_Count_All`；
2. 等待`Filter_Count_All >= Filter_Delay`，也就是等够 30° 电角度时间；
3. 时间到，查表调用`pfunclist_m1[] / pfunclist_m2[]`执行对应相的 MOS 管导通，完成换相；
4. 更新历史状态`OldHallless_State`，等待下一次过零。

> 注意：硬件 RC 滤波会引入相位滞后，实际调试需要微调，不一定严格等于理论 30°。

### 5）稳定判定

变量`count_i`累计有效过零捕获次数；**`count_i >=4`才认为过零信号稳定，函数返回 1，允许切闭环**，避免噪声误切闭环。

## 四、关键宏与结构体说明 zero_ctr.h

```c
#define DRIVE_MODE  1    //1=开启过零闭环检测；0=纯开环VVF，不会切闭环
#define FILTER_LONG 0xFF //8次采样做软件滤波
#define FirstOrderRC_LPF(Yn_1,Xn,a) Yn_1 = (1-a)*Yn_1 + a*Xn; //一阶RC滤波宏
```

- `Hallless`结构体：保存三相滤波队列、过零状态、历史状态、延时计数、转速；
- `VvvF_start`：开环强拖参数：换相间隔 Freq_T_Ref、PWM 参考电压、换相计数。

## 五、整体调用架构（工程层面）

1. 高频定时器中断（18kHz）中调用`zero_ctr_loop()`，所有状态机、过零检测在中断执行，保证实时性；
2. `g_bldc_motor1.run_flag = RUN`启动电机；`STOP`停止时调用`zero_ctr_init()`全部变量复位；
3. 闭环运行后，`g_bldc_motor1.speed`得到滤波后的转速，交给 PID，输出 PWM 占空比做调速。

## 六、调试要点（踩坑点）

1. **预定位电压不能太高**：MAX_PWM_DUTY/20，太高容易启动过流；太低转子拉不动。
2. 开环初始参数`Freq_T_Ref`、最小钳位 180：不同极对数电机需要修改；4 对极电机可以调小。
3. 如果切闭环抖动、失步：
   - 增大硬件 RC 滤波；
   - 调整软件滤波次数`FILTER_LONG`；
   - 修改`Filter_Delay = count_j/6`系数，补偿硬件相位偏移；
4. 转向：`anwerfen_sw()`中 CCW/CW 两套六步导通顺序，电机反转、启动无力，检查换相序列。
5. `DRIVE_MODE=0`，电机只会运行在开环强拖，永远不会进入闭环，用于调试开环部分。

## 七、完整工作时序总览

1. 电机 RUN → status0 预定位，固定两相通电锁住转子；
2. status1 计时，同时读三路比较器 GPIO 做滤波；
3. status2：不断缩短换相间隔，提高 PWM，开环强制六步换相，电机加速旋转；
4. 反电动势变大，`hallless_sw()`连续捕获 4 次有效过零信号，返回 1；
5. 状态切换 status=3，退出开环计时，完全由过零信号 + 动态 30° 延时做闭环换相，同时输出转速给 PID 调速。

# 🏷️ 2. `hallless_sw()` 函数详细解析

> 来源正点原子 BLDC 无感代码，在**高频定时器中断（18KHz）**中被调用。
>  返回值：`0` = 过零信号不稳定；`1` = 已经采集到稳定反电动势过零信号，可以切换闭环无感运行。
>  两大职责：
>
> 1. 对三路比较器输出的 BEMF 过零 GPIO 信号做**移位软件滤波**；
> 2. 边沿检测、计算转速、检测过零状态组合、实现**过零后延迟 30° 电角度再换相**的闭环逻辑。

```c
uint8_t hallless_sw(void)
{
    static uint8_t edge_flag = 0;   /* 过零信号稳定标志 */  
    count_j++;                      /* 运行过程时间计数 18K的中断频率为单位 */
```

- `count_j`：中断节拍计数器，**每进一次本函数 + 1**，单位 = 1/18000 s，用来度量电角度对应的时间。
- `edge_flag`静态局部变量：标记是否满足闭环切换条件。

---

## 1. 过零输入移位滤波（U/V/W 三相同样逻辑）

```c
    /* 过零信号滤波 */
    g_hallless_three.Queue_Status[0] = g_hallless_three.Queue_Status[0] << 1;
    g_hallless_three.Queue_Status[1] = g_hallless_three.Queue_Status[1] << 1;
    g_hallless_three.Queue_Status[2] = g_hallless_three.Queue_Status[2] << 1;

    /* 读取GPIO，比较器输出的三相反电动势过零电平 */
    g_hallless_three.Queue_Status[0] |= HAL_GPIO_ReadPin(HALL1_TIM_CH1_GPIO, HALL1_TIM_CH1_PIN); /* U相过零点 */
    g_hallless_three.Queue_Status[1] |= HAL_GPIO_ReadPin(HALL1_TIM_CH2_GPIO, HALL1_TIM_CH2_PIN); /* V相过零点 */
    g_hallless_three.Queue_Status[2] |= HAL_GPIO_ReadPin(HALL1_TIM_CH3_GPIO, HALL1_TIM_CH3_PIN); /* W相过零点 */
```

滤波原理：移位寄存器滤波，`FILTER_LONG = 0xFF`（8bit）

1. 每次中断，队列**左移 1bit**，把旧采样挤出去；
2. 最低位写入当前 GPIO 电平；
3. 判断：
   - `Queue_Status[x] & 0xFF == 0xFF`：最近**连续 8 次采样全部是高电平**，才认为真实电平 = 1；
   - `Queue_Status[x] & 0xFF == 0x00`：最近**连续 8 次采样全部是低电平**，才认为真实电平 = 0；
   - 既不全 0 也不全 1 → 噪声 / 抖动，直接 return 0，代表信号不稳定。

```c
    /* 过零信号U */
    g_hallless_three.Filter_Math = g_hallless_three.Queue_Status[0] & FILTER_LONG;
    if (g_hallless_three.Filter_Math == FILTER_LONG)          
    {
        g_hallless_three.QFilter_Status[0] = 1;
    }
    else if (g_hallless_three.Filter_Math == 0x00)            
    {
        g_hallless_three.QFilter_Status[0] = 0;
    }
    else
    {
        g_hallless_three.Filter_Count++;
        return 0; //采样不稳定，直接返回0，不进入后面测速、换相逻辑
    }
    // V、W相与上面U相完全一致
```

> 输出结果存到 `QFilter_Status[0],QFilter_Status[1],QFilter_Status[2]`，是滤波干净后的 U/V/W 过零电平。只要任意一相 8 次采样有跳变，直接返回 0，不让噪声触发换相。

## 2. 边沿检测 `uemf_edge()`

```c
    g_hallless_three.Filter_Edge = uemf_edge(g_hallless_three.QFilter_Status[0]);
```

`uemf_edge`只看 U 相滤波后的电平，检测电平跳变：

```c
uint8_t uemf_edge(uint8_t val)
{
    static uint8_t oldval = 0;
    if (oldval != val)
    {
        oldval = val;
        if (val == 0)
            return 0; // 1→0下降沿
        else
            return 1; // 0→1上升沿
    }
    return 2; //没有边沿，电平维持不变
}
```

返回：

- `0`：下降沿（捕捉到一次真实过零事件）
- `1`：上升沿
- `2`：电平无变化

> 代码里**用 U 相的下降沿作为过零捕获事件**，用来计算周期、转速、30° 延时时间。

### 2.1 转速计算分支

```c
    if (g_hallless_three.Filter_Edge == 0)  /* 捕获到U相下降沿，真实过零事件 */
    {
        if (count_i >= 4)                   /* 已经累计足够稳定过零事件，才计算转速 */
        {
            if (g_bldc_motor1.dir == CCW)
                g_hallless_three.Speed_RPM = ((uint32_t)SPEED_COEFF / count_j);
            else
                g_hallless_three.Speed_RPM = -((uint32_t)SPEED_COEFF / count_j);
            //一阶RC低通滤波平滑转速
            FirstOrderRC_LPF(g_bldc_motor1.speed, g_hallless_three.Speed_RPM, 0.2379);
        }
        /* 关键：计算30°电角度对应的中断计数值 */
        g_hallless_three.Filter_Delay = count_j / 6;
        g_hallless_three.Filter_Count = 0;
        count_j = 0;                        /* 清零，准备测量下一个电周期 */
        count_i++;                          /* 有效过零捕获计数，>=4才允许切闭环 */
    }
```

重点：

1. `count_j`：从上次过零到本次过零的总中断节拍。一次**60° 电角度时间**，BLDC 六步换相每步 60°；
2. 理论：30° 是 60° 的一半 → `count_j / 2`？

> 注意：这里`count_j`是**完整一个电周期（360° 电角度）的时间**，360°/12 =30°，所以 `count_j /6` 得到 30° 电角度对应的中断计数值。
>  公式：`Filter_Delay = count_j /6`，这个就是 “过零之后需要等待多少个中断节拍再换相”。

3. `count_i`：成功捕获到有效过零事件的次数；**大于等于 4，才认为反电动势信号稳定，可以进入闭环换相逻辑**。

```c
    if (g_hallless_three.Filter_Edge == 1) //上升沿，直接清零计时，不做计算
    {
        g_hallless_three.Filter_Count = 0;
        count_j = 0;
    }
    if (g_hallless_three.Filter_Edge == 2)  /* 长时间没有边沿跳变，电机几乎停转 */
    {
        g_hallless_three.Filter_Count++;
        if (g_hallless_three.Filter_Count > 15000)
        {
            g_hallless_three.Filter_Count = 0;
            g_hallless_three.Speed_RPMF = 0;  //超时，判定电机停止
        }
    }
```

- 长时间没有边沿跳变，说明没有反电动势，判定电机停转，速度置 0，防止卡死。

## 3. 闭环换相逻辑（核心：检测过零状态变化 + 延时 30° 再换相）

```c
    if (count_i >= 4)                       /* 已经捕获4次有效过零，信号稳定 */
    {
        count_i = 4;                        //上限锁死4，不再累加
        edge_flag++;
        if (edge_flag >= 2)                 //再多等待若干次中断，彻底稳定
        {
            edge_flag = 2;
            /* 把U/V/W滤波过零电平打包成一个状态码Hallless_State */
            g_hallless_three.Hallless_State = 
                g_hallless_three.QFilter_Status[0] 
                | (g_hallless_three.QFilter_Status[1] << 1) 
                | (g_hallless_three.QFilter_Status[2] << 2);
```

- 将三路过零信号组合为`Hallless_State`，取值 1~7，代表三相 BEMF 高低电平组合；
- 保存`OldHallless_State`，对比前后两次状态，判断**是否发生过零状态跳变**。

```c
            if (g_hallless_three.Hallless_State != g_hallless_three.OldHallless_State)      
            {
                g_hallless_three.Filter_Count_All++; //状态发生改变，代表检测到过零，启动延时计数器
            }

            /* 等待：过零之后，等待够30°电角度时间Filter_Delay */
            if (g_hallless_three.Filter_Count_All >= (g_hallless_three.Filter_Delay))       
            {                
                g_hallless_three.Filter_Count_All = 0;
                if (g_hallless_three.Hallless_State != g_hallless_three.OldHallless_State)  
                {
                    /* 到达延时时间，执行换相 */
                    if (g_bldc_motor1.dir == CCW)
                    {
                        g_bldc_motor1.pos--;                                                
                        pfunclist_m1[g_hallless_three.Hallless_State - 1]();  //查表，CCW导通表              
                    }
                    else
                    {
                        g_bldc_motor1.pos++;                                                
                        pfunclist_m2[g_hallless_three.Hallless_State - 1]();  //查表，CW导通表              
                    }
                }
                g_hallless_three.OldHallless_State = g_hallless_three.Hallless_State ;      
            }
        }
        return 1; //返回1：信号稳定，上层zero_ctr_loop收到返回1，就切status=3，退出开环强拖
    }
    else
        return 0; //count_i不足4次，信号不稳定，返回0，继续开环强拖
}
```

### 闭环换相时序拆解

1. 检测到`Hallless_State != OldHallless_State` → **检测到反电动势过零事件来了**，开始`Filter_Count_All`计数；
2. `Filter_Count_All`每进一次中断函数 + 1；
3. 当计数值 ≥ `Filter_Delay(count_j/6)`，代表已经过完 30° 电角度；
4. 执行查表：`pfunclist_m1[]`/`pfunclist_m2[]`是函数指针数组，数组每一项是`m1_uhvl()`、`m1_uhwl()`这类 MOS 管导通函数，直接输出六步驱动；
5. 更新`OldHallless_State`，保存本次状态，等待下一次过零跳变。

> ⚠️重要：硬件 RC 滤波电路会带来相位滞后。**理论 30°，实际调试往往要把`count_j/6`改成更小，比如`count_j/7`、`count_j/8`来补偿硬件相移，否则电机抖动、无力、发热。**

## 4. 上层如何使用 hallless_sw ()（回到 zero_ctr_loop）

```c
#if (DRIVE_MODE)                                /* 过零闭环控制 为0开环控制 */
    switch_hallless = hallless_sw();/* 检测过零信号 稳定后切换至闭环 */

    if (switch_hallless == 1)

    }
#endif
```

- 只要`hallless_sw()`返回`1`，说明已经采集足够稳定 BEMF 信号，状态机跳转到`case3`，之后**不再执行开环的定时换相逻辑**，全部换相动作由`hallless_sw()`内部的函数指针查表完成。
- 如果`DRIVE_MODE=0`，这一段编译不生效，电机永远运行在开环 VVVF 强拖。

## 6. 常见故障点和`hallless_sw`的关系

1. **电机一直开环跑，切不到闭环**：
   - 比较器硬件没输出；噪声太大，`hallless_sw`一直返回 0；`count_i`永远达不到 4；
2. **一进入闭环就抖动、失步**：
   - 硬件 RC 相位偏移，`Filter_Delay=count_j/6`理论值不合适，要调小；软件滤波`FILTER_LONG`过大过小；
3. **低速闭环无力发热**：
   - 过零检测不准，延时角度不对；中断频率不足。
4. **电机能启动闭环，但反转**：
   - `pfunclist_m1/m2`函数指针数组的导通顺序和你的电机不匹配。

# 🏷️ 3. 闭环换相逻辑逐行详细解释

> 这段代码运行在 18kHz 定时器中断内，前提：`hallless_sw()`前面已经完成**GPIO 采样→移位滤波→得到干净的 U/V/W 过零电平`QFilter_Status[]`**。
>  进入本段的条件：`count_i >=4`，代表已经成功捕获至少 4 次 U 相有效过零边沿，认为反电动势采样稳定，可以进入闭环换相逻辑。

```c
if (count_i >= 4)                       /* 已经捕获4次有效过零，信号稳定 */
{
    count_i = 4;                        //上限锁死4，不再累加
    edge_flag++;
    if (edge_flag >= 2)                 //再多等待若干次中断，彻底稳定
    {
        edge_flag = 2;
```

1. `count_i >=4`：
   `count_i` 在 U 相下降沿（真实过零事件）的时候才会 + 1；代表已经连续抓到多次有效的反电动势过零点，排除启动阶段噪声、开环干扰。
   `count_i =4`：做饱和锁死，防止变量无限溢出，大于 4 之后就固定为 4。
2. `edge_flag++` 和 `if(edge_flag >=2)`
   `edge_flag`是函数内部`static`静态变量。

> 目的：**再多缓冲几个中断节拍，防止刚满足 count_i=4 瞬间，还有残余噪声，立刻执行换相导致误动作**。
>  不是马上就干活，再多等 2 次中断调用，确认采样持续稳定，才正式开启闭环换相逻辑；达到 2 之后就一直保持等于 2，不再上涨。

## ① 组装三相过零状态码 Hallless_State

```c
        g_hallless_three.Hallless_State = 
            g_hallless_three.QFilter_Status[0] 
            | (g_hallless_three.QFilter_Status[1] << 1) 
            | (g_hallless_three.QFilter_Status[2] << 2);
```

- `QFilter_Status[0]`：U 相滤波后电平 (0/1)
- `QFilter_Status[1]`：V 相滤波后电平 (0/1)
- `QFilter_Status[2]`：W 相滤波后电平 (0/1)

把三相状态压缩成一个整数：
 bit0 = U，bit1 = V，bit2 = W

> 示例：U=1，V=0，W=1 → `1 | (0<<1) | (1<<2) = 1 + 0 +4 =5`

BLDC 无感反电动势只会出现 **1~7 中非 0 的 6 种有效组合**，正好对应 6 个电角度区间，也就是和霍尔传感器的 6 个霍尔状态完全等效。

> 👉 这里就把**比较器输出的反电动势过零信号，模拟出了虚拟霍尔状态**。

`OldHallless_State`用来保存**上一次中断的虚拟霍尔值**。对比新旧值，就知道：三相过零状态有没有发生跳变 = 是否发生过零事件。

## ② 检测过零事件到来，开启延时计时

```c
        if (g_hallless_three.Hallless_State != g_hallless_three.OldHallless_State)      
        {
            g_hallless_three.Filter_Count_All++; //状态发生改变，代表检测到过零，启动延时计数器
        }
```

> 关键点：**检测到 Hallless_State 变化，仅仅代表发生了反电动势过零点，不能立刻换相！**

BLDC 无感核心知识点：

> 反电动势过零点，超前理想换相点 **30° 电角度**。
>  如果检测到过零马上换相，会提前 30°，电机力矩下降、抖动、发热。
>  必须：**检测到过零事件 → 开始计时 → 等 30° 电角度时间到 → 再执行换相**。

- `Filter_Count_All`：延时计数器，每进一次中断就 + 1；
- 只有虚拟霍尔状态发生跳变（过零来了），才开始累加这个计数器。

> ⚠️注意：这里不是 “一检测跳变就赋值 0 再开始加”；只要状态持续不一样，就一直往上计数。

## ③ 判断 30° 延时时间是否到达

```c
        if (g_hallless_three.Filter_Count_All >= (g_hallless_three.Filter_Delay))       
        {                
            g_hallless_three.Filter_Count_All = 0;
            if (g_hallless_three.Hallless_State != g_hallless_three.OldHallless_State)  
            {
                /* 到达延时时间，执行换相 */
                if (g_bldc_motor1.dir == CCW)
                {
                    g_bldc_motor1.pos--;                                                
                    pfunclist_m1[g_hallless_three.Hallless_State - 1]();  //查表，CCW导通表              
                }
                else
                {
                    g_bldc_motor1.pos++;                                                
                    pfunclist_m2[g_hallless_three.Hallless_State - 1]();  //查表，CW导通表              
                }
            }
            g_hallless_three.OldHallless_State = g_hallless_three.Hallless_State ;      
        }
```

### 变量回顾

`Filter_Delay = count_j /6`

- `count_j`：上一次 U 相过零到本次 U 相过零的总中断节拍，对应一个完整 360° 电周期；
- `count_j/6` 理论算出 30° 电角度对应的中断计数值。

逻辑拆解：

1. `Filter_Count_All >= Filter_Delay`：等待的中断节拍已经达到理论 30° 电角度，延时时间到。
2. `g_hallless_three.Filter_Count_All = 0;`：清空延时计数器，准备下一次过零延时。
3. 再次做判断 `Hallless_State != OldHallless_State`：二次确认，防止噪声导致的假触发。
4. 执行换相：
   - `g_bldc_motor1.pos++/pos--`：电机转子位置计数，用于位置观测；
   - `pfunclist_m1[]`、`pfunclist_m2[]`是**函数指针数组**：
     - 下标：`Hallless_State‑1`（状态是 1~6，数组下标从 0 开始）
     - 数组内存放各个导通函数：`m1_uhvl()`、`m1_uhwl()`……
     - 调用之后，直接输出六路 PWM，打开对应 MOS 管，完成一次六步换相。
     - m1 数组对应逆时针 CCW；m2 数组对应顺时针 CW。
5. `OldHallless_State = Hallless_State`：**更新历史状态，把刚刚完成换相这一刻的虚拟霍尔状态保存下来**，用于下一轮判断状态跳变。

> ✨完整时序复述：
>
> 1. 转子转动，BEMF 发生过零 → U/V/W 电平变化 → `Hallless_State != OldHallless_State`；
> 2. `Filter_Count_All`开始每中断 + 1；
> 3. 计数达到`Filter_Delay`（30° 电角度时间）；
> 4. 调用 pfunclist 执行 MOS 换相；
> 5. 更新 OldHallless_State，等待下一次过零跳变。

## ④ 返回上层状态机

```c
        return 1;
    }
    else
        return 0;
}
```

- `return 1`：代表过零信号稳定；上层`zero_ctr_loop()`收到`switch_hallless=1`，把`g_zero_ctr_status=3`，**退出开环强拖，进入闭环模式**。
- 进入 case3 之后，开环的定时换相（`anwerfen_sw()`）不再运行；**所有换相全部由 hallless_sw 内部这套 “虚拟霍尔 + 30° 延时” 逻辑驱动**。

# 容易踩坑的细节（重点）

1. **Filter_Delay 是动态变化的，不是固定常量**
   每捕获一次 U 相过零边沿，会用当前转速算出`Filter_Delay = count_j /6`；转速越高，count_j 越小，30° 对应的中断节拍就越小。实现：**转速变化，延时时间自动跟随转速变化**。
2. 硬件 RC 滤波、比较器会引入相位滞后
   理论值`count_j/6`在很多电机板子上并不完美。

- 如果电机抖动、无力、发热：需要调小分母，改为`count_j/7`、`count_j/8`，补偿硬件带来相位偏移。

3. `Hallless_State`不能等于 0
   因为反电动势三相电平不会出现 000，代码`pfunclist_m1[Hallless_State‑1]`，如果 state=0，下标 =-1，数组越界；前面的移位滤波逻辑会屏蔽掉这种非法状态。
4. 进入闭环之后，**不再依靠定时器计时做换相**，完全由反电动势事件驱动换相；转速是结果，不是换相依据。
5. edge_flag 的作用：软防抖，避免刚切闭环瞬间采样不稳定，防止刚 count_i=4 立刻就乱换相。

# 为什么 `Filter_Delay = count_j / 6` 代表 30° 电角度

先把关键变量定义摆清楚：

> `count_j`：**两次相邻 U 相过零下降沿之间的中断计数**，代表一整个**360° 电角度**的时间（BLDC 一个完整电周期）。
>  中断频率 18kHz，每进一次`hallless_sw()`，`count_j++`。

> 360° ÷ 12 = **30°**
>  所以：30° 电角度的中断节拍数 = 总电周期节拍数 `count_j` ÷ **12**
>  ❗但是代码写的是 `count_j / 6`，这里很容易混淆，下面讲清楚源码的真实物理含义。

## 1、BLDC 无刷电机电角度基础

三相 BLDC 六步换向，一个完整电周期 360° 电角度，分为 6 个扇区，每个扇区 **60° 电角度**。

- 每发生 1 次换相，转子走过 60° 电角度。
- 反电动势**过零点，出现在每个 60° 扇区的正中间，也就是距离上一次换相 30° 电角度位置**。

> 经典无感 BEMF 规则：
>  检测到**反电动势过零点**，此时距离**理想换相点还剩 30° 电角度**，必须延时 30° 再换相。

---

## 2、count_j 到底统计的是多少度？

看源码捕获`count_j`的位置：

```c
if (g_hallless_three.Filter_Edge == 0)  /* U相下降沿（过零事件） */
{
    ...
    g_hallless_three.Filter_Delay = count_j / 6;
    count_j = 0;        //捕获到U相过零，立刻清零count_j
}
```

👉 `Filter_Edge ==0` 是 **U 相 BEMF 的下降沿过零点**。

- 本次 U 相下降沿 → 下一次 U 相下降沿：转子转过**完整 360° 电角度**。
- `count_j` 就是这 360° 电角度所对应的中断总次数。

| 电⁠角⁠度 | 占 360° 比⁠例 | 中⁠断⁠节⁠拍 |
| --- | --- | --- |
| 360° | 1 | `count_j` |
| 180° | 1/2 | `count_j /2` |
| **60°** | 1/6 | `count_j /6` |
| 30° | 1/12 | `count_j /12` |

> 数学上：30° 应该是 `count_j /12`，**但正点原子源码写的是 `count_j /6`，等于 60° 的时间，这里怎么回事？这是很多人读代码的最大迷惑点。**

### 核心真相：源码里不是 “过零之后等 30°”，而是**过零状态跳变时刻本身就已经滞后了真实物理过零点 30°**

> 注意：代码中**并不是用 U 相下降沿这个边沿作为 “过零触发点” 去启动 Filter_Count_All！！**
>
> - `count_j` 是用 U 相下降沿做周期测量（测速用），算出`Filter_Delay`；
> - 但是**真正启动延时计数器`Filter_Count_All++`的触发条件不是 U 相边沿，而是 `Hallless_State（三相组合状态）发生跳变`**。

物理时序拆解：

1. 真实物理世界：绕组反电动势到达**真正过零点（0V）**；
2. 经过硬件 RC 低通滤波 + 比较器，三相电平发生翻转，**虚拟霍尔`Hallless_State`发生跳变**。 👉 ** 这个` Hallless_State跳变事件，本身就已经晚于真实BEMF过零点约30°电角度**。 也就是：当代码检测到  `Hallless_State != OldHallless_State` 这一刻，转子已经又往前走了接近 30°。

> 所以此时不再需要再等完整 30°，只需要再等**剩余的另外 30°，也就是 60° 总区间的一半**。
>  而一个 60° 扇区时间 = `count_j /6`。

> 总结公式来源：
>
> - 360° 电周期节拍 = `count_j`
> - 单个扇区 60° 电角度节拍 = `count_j /6` 代码：`Filter_Delay = count_j /6`，等待一个扇区（60°）的时间。 因为硬件电路已经吃掉前面约 30° 相位，软件再等`count_j/6`（60°），叠加后整体等效延时接近理论需要的 30°。

> 不是数学理想 30° = count_j/12，而是**硬件相移 + 软件延时共同凑出总 30° 电角度延时**。

## 3、转速变化，Filter_Delay 自动跟随

- 电机转速变快 → 转子转的快 → 360° 电周期的中断计数`count_j`数值变小；
- `Filter_Delay = count_j/6`也跟着自动变小；

> 转速越高，需要等待的中断节拍越少，完美适配不同转速，**不是写死的固定常数**。这是 BEMF 无感很关键一点：延时不能写死，必须随转速动态计算。

举个数字例子，假设 18kHz 中断：
 假设电机转速对应的 360° 电周期 = 720 个中断节拍（`count_j=720`）

- 360° →720 节拍
- 60° →720/6 =120 节拍，即`Filter_Delay=120` 软件检测到 Hallless_State 跳变之后，再数 120 次中断再换相。

转速升高一倍：电周期变短，`count_j=360`
`Filter_Delay=360/6 = 60`，等待节拍自动减半。

## 4、为什么实际调试经常要改分母？

硬件 RC 滤波电路电阻电容参数不同，带来的相位偏移不是精准的 30°，会偏大或偏小：

1. 电机抖动、力矩弱、发热：说明**软件等待时间太长，实际总延时大于 30°**；需要增大分母：`count_j /7`、`count_j/8`，减少等待节拍。
2. 启动闭环就失步：延时太短，换相提前，改用`count_j/5`，增加等待节拍。

> 👉 这就是正点代码注释写的：
> `/* 延迟30°换相，因为硬件上低通滤波器和软件延迟的原因，实际延迟角度需小于30° */`

## 5、容易混淆的两个事件（重中之重，90% 人看漏）

1. **U 相下降沿 Filter_Edge==0**：用来测量电周期，更新`count_j`、计算`Filter_Delay`；只是测速计时事件，**不启动换相延时**。
2. **Hallless_State != OldHallless_State**：三相虚拟霍尔状态跳变，这个才是**启动 Filter_Count_All 延时计数的事件**。

> 不要误以为：U 相过零边沿到来，立刻开启 Filter_Count_All 开始计时。源码不是这样！
>  计时起点是【三相组合状态跳变】，不是 U 相边沿。两者在时间上因为硬件滤波已经错开几十度电角度。

## 极简一句话总结

> `count_j`是完整 360° 电周期的中断计数值，`count_j/6`代表 60° 电角度的中断节拍。
>  代码没有在真实 BEMF 物理过零点开始计时；**硬件 RC + 比较器已经滞后真实过零点约 30°，软件再延时 count_j/6（60°），两者叠加补偿，逼近理想需要的 30° 换相延时**。
>  硬件参数不一样，这个理论值就不准，必须现场调分母。

# 🏷️ 4. 为什么：硬件滞后约 30° + 软件再等`count_j/6`(60°)，整体等效得到 30° 换相偏移

> 先澄清一个极易搞反的概念：**相位滞后 = 事件在时间上往后推迟发生**。
>  真实 BEMF 过零点（物理）→经过 RC 滤波 + 比较器→输出跳变（软件看到的 Hallless_State 跳变），这个过程**把事件向后推迟了 Δφ 电角度**，本方案硬件设计目标让 Δφ≈30°。

> 理想理论要求：
>  从【真实 BEMF 过零点】算起，往后再走**30° 电角度，执行换相**。
>  即：`真实过零点 →(+30°)→换相点`

## 1）把时间轴拆开（电角度从 0 开始）

1. **0°：真实物理 BEMF 过零点（绕组反电动势穿过 0V）**
   此时 MOS 还没有任何动作，这是绕组内部真实事件；RC 滤波电路还没反应，GPIO 电平不变，软件完全看不到这个点。
2. **+30°：硬件 RC + 比较器输出才翻转 → Hallless_State 发生跳变**> ⚠️硬件把 “过零事件” 向后推迟了 30°！
   >  软件**只能在这 + 30° 位置，才检测到`Hallless_State != OldHallless_State`，才开始启动软件计时器`Filter_Count_All`**。
   >  👉软件计时起点不是 0°，而是已经走到**+30° 电角度的位置**。
3. 从 + 30° 位置开始，软件再等待 `Filter_Delay = count_j/6 =60°电角度`，到达：
   $30^\circ + 60^\circ = 90^\circ$
   哎？这里得到 90°，明显不对，说明我上一轮表述有错误，纠正：

> ❗之前的表述 “硬件滞后 30° 软件再等 60° 凑 30°” 是错误，那是逻辑矛盾。
>  重新读源码注释：
>
> ```c
> /* 延迟30°换相，因为硬件上低通滤波器和软件延迟的原因，实际延迟角度需小于30° */
> g_hallless_three.Filter_Delay = count_j / 6;  /* 30°所需时间，理论值 */
> ```
>
> **源码注释明确写：`count_j/6`就是理论 30° 的时间。那数学上 360/count_j 是整周期，`count_j/6 = 60°`，注释为什么说是 30°？根源：count_j 并不是 360°！**

## 2）真正根源：count_j 统计的不是 360°，而是**180° 电周期（U 相一次完整正负半波）**

看代码捕获边沿：

```c
if (g_hallless_three.Filter_Edge == 0)  // uemf_edge返回0：U相 1→0 下降沿
{
    ...
    g_hallless_three.Filter_Delay = count_j / 6;
    count_j = 0;
}
```

`uemf_edge(val)`返回 0，是**U 相 BEMF 从高变低的下降沿过零点**。
 U 相 BEMF：一个电周期 360° 里面会出现：

- 0° 附近：上升沿过零（0→1）
- 180° 附近：下降沿过零（1→0，代码捕获的这个边沿）

👉 **代码每次捕获的是间隔 180° 的下降沿，不是 360°！！！**

> `count_j` = 两次 U 相下降沿之间的中断节拍 = **180° 电角度的总时间**，不是 360°。

数学就对上源码注释了：

- `count_j` ⇒ **180° 电角度**
- `count_j /6` ⇒ $180^\circ /6 = \boldsymbol{30^\circ}$ ✔

> 这就是注释写 “`count_j/6`为 30° 所需时间，理论值” 的真正原因！

> 我前面回答错误地把 count_j 当成 360°，造成矛盾，现在纠正：
>  程序只抓 U 相**下降沿过零点**，相邻两次下降沿相隔 180° 电角度，count_j 计量这 180° 的中断节拍。
> $Filter\_Delay = \frac{count\_j}{6} = \frac{180^\circ}{6}=30^\circ$

### 时序现在就通顺了

1. **真实 BEMF 过零点（物理）0°**；
2. 经过 RC 硬件滤波、比较器，产生相位滞后 Δφ；软件看到`Hallless_State跳变`（软件计时起点）；
3. 软件从这个跳变点开始，计时等待`count_j/6`，理论等于**30° 电角度**，时间到执行换相；

> 理想无硬件相移：
>  真实过零点 (0°) →软件检测到跳变 (0°) →软件等 30° →换相点在 30°，完美符合无感理论要求。

> 但是现实硬件 RC 滤波器**一定会引入相位滞后 Δφ（0~ 几十度）**：
>
> - 硬件滞后 Δφ：软件看到跳变的时刻变成真实过零点之后 Δφ 位置；
> - 软件再等理论 30°；
> - 总换相偏移 = Δφ + 30°； 所以源码注释提醒：**实际延迟角度需要小于 30°**。 硬件已经带来一部分滞后 Δφ，软件这边不能再严格等 30°，要把软件等待时间改小，比如改成`count_j/7`、`count_j/8`，抵消硬件 RC 带来的相移。

## 3）举数字例子（18kHz 中断）

假设电机运行，U 相两次下降沿（间隔 180° 电角度）一共占用 720 个中断节拍：
$count\_j =720 \quad \Leftarrow \text{对应180°电角度}$
$Filter\_Delay = count\_j/6 = 120 \text{ 个中断节拍} \Leftarrow \text{理论30°}$

- 如果硬件 RC 带来 Δφ=10° 滞后： 总偏移 = 10° +30° =40°，超过理想 30°；电机抖动力矩变差。 解决：修改分母，`Filter_Delay = count_j/8 =90节拍`，软件等待变成 22.5°，总和 10+22.5≈32.5° 接近理想。

## 4）总结关键点（解决你的疑惑）

1. `count_j`是**U 相两次下降沿过零点之间的计数，对应 180° 电角度，不是 360°**。
2. 所以：$count_j/6 = 180°/6 = \boldsymbol{30°}$，这就是注释写 “30° 所需时间，理论值” 的来源。
3. 理想：软件检测到过零状态跳变，再等`count_j/6`（30°）换相。
4. **硬件 RC 低通滤波器会引入额外相位滞后 Δφ**，相当于软件计时起点本身就往后挪了 Δφ；
5. 于是真实总相位偏移 = 硬件 Δφ + 软件 30°，大于理论需要的 30°。
6. 因此调试时，要增大分母（/7 /8），**减小软件侧等待角度，用来补偿硬件的相位滞后**。

> 误区回顾：之前误以为 count_j 是 360°，导致出现 “硬件 30°+ 软件 60° 得到 30°” 这种逻辑矛盾，根源就是：代码只捕获 U 相**下降沿过零**，每 180° 才触发一次 count_j 清零，不是 360°。

# 🏷️ 5、什么是 U 相一次完整正负半波...

# U 相一次完整正负半波 & 180° 电角度

## 1、BLDC 反电动势 BEMF 基础

BLDC 电机转子永磁体旋转，定子 U 相绕组会感应出正弦形状的**反电动势（BEMF）**。

> 电角度：是针对定子绕组感应电压的角度，**和机械角度不一样**。
>  一对极（1 对 N‑S 磁铁）：**电角度 = 机械角度**；
>  4 对极电机：转子机械转一圈，电角度转 4×360°。

对于任意一相（U 相）反电动势正弦波：
$E_u = E \cdot \sin(\theta_{elec})$
$\theta_{elec}$：**电角度**。

- $0^\circ < \theta_{elec}<180^\circ$：$\sin\theta>0$ → **正半波**，U 相反电动势电压 > 0；
- $180^\circ < \theta_{elec}<360^\circ$：$\sin\theta<0$ → **负半波**，U 相反电动势电压 < 0；

> - **正半波：0°～180° 电角度**
> - **负半波：180°～360° 电角度** ➡️**一次正半波 + 一次负半波 = 完整正弦周期 = 360° 电角度**。

### 什么叫「U 相一次完整正负半波」

U 相从 0°→180°（正半波），再从 180°→360°（负半波），走完一遍，就是**一次完整正负半波，360° 电角度**。

---

## 2、U 相过零点在哪里

正弦反电动势过零点就是 $E_u=0$ 的位置：

1. $\boldsymbol{\theta=0^\circ}$：电压由负变正 → **上升沿过零（0→+）**
2. $\boldsymbol{\theta=180^\circ}$：电压由正变负 → **下降沿过零（+→0）**
3. $\boldsymbol{\theta=360^\circ}$：又由负变正，等价 0°，上升沿过零。

> 相邻两个**下降沿过零点**之间：$180^\circ \to 360^\circ+180^\circ$，间隔是**180° 电角度**！
>  也就是：
>
> - 第 1 次下降沿：180°
> - 下一次 U 相下降沿：180°+180° = 360°+180° = 540° 两者相差**180° 电角度**。

👉 源码里面 `uemf_edge()` 返回 0，就是捕获这个**U 相下降沿过零（正半波结束、进入负半波的那个零点）**。

```c
if (val == 0)
    return 0;  //1→0，下降沿，U相BEMF从正翻负，θ=180°、540°……位置
```

### 重点：count_j 什么时候清零

```c
if (g_hallless_three.Filter_Edge == 0)  //捕获U相下降沿过零
{
    g_hallless_three.Filter_Delay = count_j / 6;
    count_j = 0;   //捕获到下降沿，立刻清零重新计数
}
```

- 本次 U 相下降沿（180°）清零`count_j`，`count_j`开始累加；
- 直到**下一次 U 相下降沿（540°）再次触发**，读取 count_j，然后清零。
- 180° 到 540°，差值 = **360°‑180° = 180° 电角度**。

✅ 所以：**`count_j`统计的就是两次 U 相下降沿之间的时间，对应电角度 180°。**

> ⚠️不是完整的正负半波（完整正负半波是 360°）！
> `count_j` 对应的是：**半个 BEMF 正弦周期**：
>  从一个下降沿 (180°) →下一个下降沿 (540°)：
>  走过：负半波 (180~360°)+ 正半波 (360~540°)，刚好**半个正弦波周期 = 180° 电角度**。

---

## 3、数学推导为什么 count_j /6 =30°

- `count_j`：180° 电角度对应的中断总节拍。$\text{每1°对应的节拍数}= \frac{count\_j}{180}$$30^\circ\text{对应的节拍数}= 30 \times \frac{count\_j}{180}= \frac{count\_j}{6}$ 👉 这就是注释写`count_j/6为30°理论时间`的数学来源。

## 4、用波形直观梳理 U 相 BEMF

| 电⁠角⁠度 | BEMF 状⁠态 | 过⁠零⁠事⁠件 |
| --- | --- | --- |
| 0° | 负→正 | 上⁠升⁠沿⁠过⁠零（代⁠码⁠不⁠捕⁠获） |
| 0°~180° | 正⁠半⁠波 | 电⁠压 > 0 |
| 180° | 正→负 | **下⁠降⁠沿⁠过⁠零（代⁠码⁠捕⁠获！Filter_Edge=0，count_j 读⁠取⁠并⁠清⁠零）** |
| 180°~360° | 负⁠半⁠波 | 电⁠压 < 0 |
| 360° | 负→正 | 上⁠升⁠沿⁠过⁠零（代⁠码⁠不⁠捕⁠获） |
| 360°~540° | 正⁠半⁠波 | 电⁠压 > 0 |
| 540° | 正→负 | **下⁠降⁠沿⁠过⁠零（再⁠次⁠捕⁠获，读⁠取 count_j，清⁠零）** |

> 180° →540°，间隔 180° 电角度，`count_j`记录这段时间的中断次数。

## 5、为什么代码**只抓下降沿，不抓上升沿？**

硬件比较器输出经过 RC 低通滤波，上升沿、下降沿的相位偏移不完全对称。正点原子这套代码只选用 U 相的下降沿作为周期测量点，固定用这一个边沿做周期计时，简化测速。

> 缺点：只用半个周期做测速；优点逻辑简单，不需要区分上升 / 下降两套计算。

## 6、容易混淆概念总结

1. **完整正负半波（正 + 负）**：0~360° 电角度，完整正弦波，间隔 360°；
2. **两次 U 相下降沿之间**：180° →540°，只有**180° 电角度（半个正弦波）**，这是`count_j`测量对象；
3. 所以：$\boldsymbol{count_j \div6 = 30^\circ}$（理论值）。
4. 硬件 RC 滤波会带来额外相位偏移，所以实际调试分母要改成 7、8 来补偿。

## 补充举个数字例子

假设电机运行，两次 U 相下降沿之间，中断一共计到 `count_j = 600`：

- 600 个中断节拍 =180° 电角度
- 每 1° =600÷180≈3.333 个节拍
- 30° 需要节拍：30 ×3.333 =100 节拍
- `count_j/6 =600/6=100`，完全吻合。

> 如果 count_j 统计的是完整 360°，那 30° 就应该是 count_j/12，就和源码注释冲突。
