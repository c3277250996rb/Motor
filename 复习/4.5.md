# 🏷️ 4.5.1 DAC简介

### 1. DAC是什么？和ADC区别

- ADC用于采集外部模拟信号
- DAC用于根据数字量生成模拟电压
- ADC是输入，DAC是输出

---

### 2. STM32F407 DAC主要特点

重点：

##### 12位DAC

STM32F407 DAC分辨率：

```
12bit
```

意味着：

```
0~4095
```

共：

$$
2^{12}=4096
$$

例如：

参考电压：

$$
V_{REF}=3.3V
$$

数字量：

$$
Data=2048
$$

输出：

$$
V_{out}
=
\frac{Data}{4095}\times V_{REF}
$$

约：

$$
V_{out}=1.65V
$$

面试可能问：

> DAC分辨率是什么意思？

答：

表示DAC能够将满量程电压分成多少份，12bit表示4096个等级。

---

### 3. DAC输出电压范围

重点：

DAC不能输出负电压。

只能：

```
0V ~ VREF+
```

所以如果生成正弦波：

原本：

$$
y=A\sin(x)
$$

有负半周期。

需要整体上移：

$$
y=A\sin(x)+A
$$

变成：

```
0 ~ 2A
```

这也是后面DAC输出正弦波为什么需要偏置。

---

### 4. DAC输出缓冲(Buffer)

##### Buffer加入后

加入运放：

```
              Buffer


DAC ----->  +-------+
            | 运放  |
            +-------+
                |
                |
             输出
```

作用：

降低输出阻抗，提高带载能力。

|            | 开启Buffer | 关闭Buffer |
| ---------- | ---------- | ---------- |
| 输出阻抗   | 低         | 高         |
| 驱动能力   | 强         | 弱         |
| 带负载能力 | 好         | 差         |
| 输出精度   | 略有影响   | 更高       |
| 适合       | 外部使用   | 内部采样   |

---

### 5. DAC触发方式

DAC更新数据有三种方式：

##### 软件触发

CPU直接写：

```
HAL_DAC_SetValue()
```

流程：

```
CPU
 |
写DAC寄存器
 |
DAC输出
```

优点：

简单

缺点：

CPU参与

---

##### 定时器触发

例如：

TIM6产生更新事件：

```
TIM6
 |
TRGO
 |
DAC
 |
输出
```

优点：

输出周期稳定。

---

##### DMA触发

完整链路：

```
CPU配置一次
 |
 | RAM数组
 ↓
TIM6
 |
 | 更新事件 TRGO
 ↓
DMA请求
 |
 | 搬一个数据
 ↓
DAC
 |
 ↓
输出电压
```

# 🏷️ 4.5.2 DAC输出

### 1. DAC初始化流程

面试可以回答：

DAC初始化步骤：

##### ① 开启DAC时钟

例如：

```
__HAL_RCC_DAC_CLK_ENABLE()
```

---

##### ② GPIO设置模拟模式

DAC引脚不能普通GPIO输出。

例如：

PA4：

```
GPIO_MODE_ANALOG
```

---

##### ③ 初始化DAC

调用：

```
HAL_DAC_Init()
```

---

##### ④ 配置DAC通道

例如：

```
HAL_DAC_ConfigChannel()
```

配置：

- 通道
- 触发方式
- 输出buffer

---

##### ⑤ 开启DAC

```
HAL_DAC_Start()
```

---

### 2. DAC和ADC联合测试思想

实验里面：

DAC输出：

```
PA4
 |
连接
 |
ADC采集
```

流程：

```
CPU设置DAC值

      ↓

DAC输出电压

      ↓

ADC采集

      ↓

验证DAC输出是否正确
```

这个思想面试很喜欢问：

> 如何验证DAC输出？

答：

可以使用示波器直接观察，也可以使用ADC采样反馈验证。

虽然这两节只是基础，但是结合后面FOC非常有价值。

DAC常用于调试内部变量。

例如：

FOC里面：

```

角度

```

这些变量本来存在MCU内部。

可以：

```

```

输出：

# 🏷️ 4.5.3 DAC 输出三角波

### 1. DAC输出波形的本质：不断修改DAC寄存器值

三角波：

```
数字量变化序列

0
100
200
300
...
4095
...
300
200
100
0

        ↓

不断写入DAC

        ↓

PA4输出三角波
```

代码中通过：

```c
HAL_DAC_SetValue()
```

不断改变DAC输出值，实现波形。

面试回答：

> DAC本身不会产生复杂波形，本质是通过高速更新DAC输入码值，使输出电压随时间变化，从而合成各种模拟波形。

---

### 2. 波形频率 = 采样点更新频率 / 一个周期采样点数

这是最值得背的公式。

文档给出：

$$
f \approx \frac{1000}{dt \times samples} kHz
$$

其中：

- dt：每个采样点之间延时时间(us)
- samples：一个三角波周期的采样点数量

---

面试可能问：

**为什么采样点越多，波形越平滑，但是频率越低？**

因为：

一个周期时间：

$$
T=t_{update}\times N
$$

采样点N增加：

- 波形更加接近理想曲线
- 但是周期时间增加
- 输出频率降低

---

### 3. DAC生成波形的限制

##### 更新速度限制

代码里面使用：

```c
delay_us(dt)
```

控制更新速度。

但是：

当dt很小时：

```
delay_us执行时间
+
函数调用时间
+
计算时间
```

不可忽略。

所以实际频率会降低。

面试回答：

> 软件轮询方式产生DAC波形受CPU执行速度限制，高频波形一般使用定时器触发DAC+DMA。

# 🏷️ 4.5.4 DAC 输出正弦波

### 1. DMA循环模式

本节新增 DMA 在 DAC 中的典型应用。

配置：

```
DMA_CIRCULAR
```

含义：

数组：

```
[0][1][2][3]...[99]
```

发送完：

```
重新回到0
```

形成：

```
无限正弦波
```

否则：

一次 DMA：

```
0→99
```

结束后波形停止。

文档源码中 DMA 设置：

```
g_dma_dac_handle.Init.Mode = DMA_CIRCULAR;
```



------

### 2. DAC + DMA 数据方向

本实验：

```
Memory
  |
  |
 DMA
  |
  ↓
DAC
```

所以：

```
DMA_MEMORY_TO_PERIPH
```

原因：

DAC数据寄存器属于外设。
